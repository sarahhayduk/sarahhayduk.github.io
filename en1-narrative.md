# Enhancement One Narrative
## Software Engineering and Design: Numeric Overflow Coding Activity (C++)

This Numeric Overflow Coding Activity comes from CS-405 Secure Coding. The program was designed to detect that an overflow or underflow occurred, prevent it, and return the last safe value. The original implementation included only basic arithmetic functions in C++, a monolithic structure, and partial protections for numeric overflow and underflow. To address these limitations, I refactored the logic into a dedicated **SafeArithmetic.h** module that encapsulates all overflow and underflow detection across addition, subtraction, multiplication, and division. This allowed me to separate the computational engine from the testing and output logic, improving clarity and maintainability. In the original version, the logic for addition and subtraction was embedded directly in the main source file, and multiplication and division were not protected at all. By moving all arithmetic into a reusable component and expanding the coverage to all four operations, the enhancement transformed the assignment into a more complete and realistic systems-level module.

I selected this artifact for my ePortfolio because it represents one of the clearest examples of my growth in software engineering discipline, defensive coding, and system level reasoning. The original assignment was small in scope, but enhancing it into a fully modular SafeArithmetic component required me to think far beyond the basic arithmetic operations. I had to understand how different numeric types behave at their boundaries, how undefined behavior occurs in C++, and how to design a reusable module that prevents those failures before they happen. This enhancement also required me to apply the Single Responsibility Principle by ensuring that each function, **safe_add**, **safe_subtract**, **safe_multiply**, **safe_divide**, handled only one operation and that the testing harness in the main application remained completely decoupled from the arithmetic logic. This separation of concerns reflects real-world software engineering practices and demonstrates my ability to design components that can be reused independently of their original context. The enhanced test harness also uses scoped blocks and type-trait checks (such as **std::is_signed**) to ensure consistent behavior across all C++ primitive numeric types, which further strengthened the modular design. This artifact shows my ability to transform a simple academic exercise into a maintainable, extensible, and professionally relevant solution, which is why it belongs in my portfolio.
  
The learning that occurred during this enhancement was substantial. As I expanded the logic to handle overflow and underflow across addition, subtraction, multiplication, and division, I realized how many edge cases were never addressed by the original assignment or by my pseudocode in the plan proposal. Working through these gaps taught me to rely on mathematical reasoning, type limits, and structured testing rather than assumptions. I learned how to design defensive checks that anticipate failure modes, how to validate both positive and negative boundary conditions, and how to ensure predictable behavior across all numeric types. The debugging process, especially regarding multiplication, led me first to refine my test logic and then to adjust my header to correctly handle both positive and negative multipliers. These were cases I failed to see when designing the pseudocode alone. I also discovered that multiplication requires division‑based pre‑checks to avoid performing unsafe operations, and that division has its own unique hazards, such as the **MIN / -1** overflow case for signed integers and the need to explicitly detect divide‑by‑zero. Incorporating these protections deepened my understanding of how arithmetic interacts with hardware limits and why defensive programming is essential in systems‑level C++ development. This reinforced the value of iterative refinement, careful analysis of program output, and verifying correctness through comprehensive test coverage.
  
This artifact directly supports the course outcomes I selected. For Outcome 4, the SafeArithmetic module demonstrates my ability to apply well-founded engineering techniques by restructuring the original code into a reusable, modular header and implementing secure, predictable arithmetic handling. The use of templates, type traits, and boundary-aware logic shows an understanding of scalable and maintainable design. For Outcome 5, the enhancement reflects a security-focused mindset. Numeric overflow and underflow are real sources of vulnerabilities in C++ systems, and by identifying missing cases, adding complete boundary validation, and preventing undefined behavior, I created a safer and more robust solution. Overall, this artifact captures both the technical skills and the engineering maturity I have developed throughout the Computer Science program and will carry with me into my professional career.
