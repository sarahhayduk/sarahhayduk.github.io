# Enhancement Two Narrative
## Algorithms and Data Structures: Grazioso Salvare Rescue Dog Dashboard (MongoDB/Python/Dash)

The Grazioso Salvare Rescue Dog Dashboard comes from CS-340 Client/Server Development. The original project was a Jupyter Source File that used a single anchored regex pattern to filter dogs by breed, which meant only exact matches appeared and mixed breeds were excluded. This limitation made the dashboard less accurate and highlighted the need for a more flexible search algorithm. Because the enhancement required evaluating pattern-matching strategies, analyzing computational tradeoffs, and improving data-driven filtering, it aligns directly with the Algorithms and Data Structures category.

For this enhancement, I migrated the dashboard from a Jupyter Notebook to a standalone Python file to ensure consistent execution and proper rendering of the Dash interface. After updating deprecated imports, Jupyter stopped serving the dashboard through the expected local URL and instead embedded the app output inside the notebook, which broke the intended layout and interaction model. Running the project as a dedicated Python script restored the correct environment, allowed terminal-based execution, and provided a stable foundation for further improvements. I then redesigned the breed matching logic into a dual-mode algorithm with **Strict** and **Expanded** options tied to a UI dropdown. Strict Mode uses anchored regex for exact matches, while Expanded Mode uses unanchored regex to allow partial matches and include mixed breeds. To support this, I introduced a small helper function that dynamically constructs either anchored or unanchored patterns, reducing duplication and making the query-building process more systematic. Implementing this required understanding how MongoDB executes regex queries and how anchored versus unanchored patterns affect time complexity. Anchored regex reduces the search space by matching only at the beginning and end of the string, which generally keeps execution closer to **O(n)**. Unanchored regex, however, allows matches anywhere within the field, which can force MongoDB’s regex engine to scan more characters and approach worst case **O(n * m)** behavior depending on the pattern length. I also had to consider the memory tradeoffs of buffering these results in Dash, since Expanded Mode can return larger datasets that must be temporarily stored and rendered. Designing the algorithm around these tradeoffs allowed me to balance strictness and inclusiveness in a way that improves both accuracy and usability.

Most of the debugging I encountered was related to UI behavior rather than the algorithm itself. Because the rescue‑type buttons controlled the filtering, selecting the new dropdown initially caused the dashboard to revert to the default “All Animals” view. I resolved this by using a **dcc.Store** component to preserve the last selected rescue type while also providing a cleaner user experience by resetting the dropdown to Strict Mode when switching between rescue buttons. This required restructuring the callback into a multi-input, multi-output controller that detects which UI element triggered the update, ensuring predictable state transitions across the dashboard. The algorithm’s correctness was validated by checking the dataset directly using the table’s column sorting features. For example, in Water Rescue, switching the dropdown between Strict and Expanded modes produced no visible change. I confirmed that this was not an algorithm flaw; it was simply because no mixed‑breed variants met the sex and age criteria for that rescue type. This verified the 
algorithm was functioning as intended. Lastly, I configured the application to run as a standalone Flask server using the **if \_\_name\_\_ == “\_\_main\_\_”:** block. This ensured I could launch the Python file straight from the terminal and completely removed the dependency on Jupyter’s internal server.

This artifact directly supports the course outcome I selected for this category. For Outcome 3, the dual-mode breed-match algorithm demonstrates my ability to design and evaluate computing solutions using algorithmic principles while managing the tradeoffs involved in real world design choices. Implementing anchored and unanchored regex models required analyzing their time-complexity behavior in MongoDB, considering memory implications when buffering larger result sets, and balancing strictness versus inclusiveness in data filtering. Additionally, restructuring the callback logic and introducing client-side state storage required careful reasoning about data flow and the underlying structures Dash uses to manage component state. While the theoretical complexity differs between the two modes, the performance impact is negligible on 
modern hardware, which further reinforces the importance of evaluating both algorithmic theory and practical execution. Overall, this artifact reflects the growth of my algorithmic thinking and my ability to apply computational analysis to improve both functionality and user experience.
